# 录屏（Codex App 实操）（v15.0）

**v15 拍什么**：工具教程的实操镜按「输入一句大白话提示词 → 默认直出 → 加一句关键提示词 → 精修后成品交互」连续录，供 `prompt_iter_workbench` 的 `before_source` / `after_source` 与后续全屏交互使用；默认直出那一版要真实保留，正是口播里“哪里差”的反例画面。终端只录安装那一下，放在第一分钟之后。录好的文件登记 `asset-ledger.jsonl`，同一页面换不同操作也要拍出真正不同的画面状态，装片前由 `precheck-episode.sh --stage assets` 查重。

## 首选：DeepSeek Harness 常驻录屏师（2026-11-17 起）

把 Harness 当作便宜的录屏 Agent：告诉它要拍什么，具体怎么操作由它自己决定。不要用逐步脚本加层层守卫把它框住。Claude 不亲自录屏，也不盯屏幕。

- **启动**：用户在 Harness **应用**里开一个对话，把待命提示词贴进去，模板见 [dsh-standby-prompt](../kit/docs/dsh-standby-prompt.md)。从命令行启动的 dsh 拿不到应用的辅助功能权限，点击会被系统拒绝，所以不要用。Harness 应用需要“辅助功能”和“屏幕录制”两个权限，由用户本人开启。
- **收件箱**：`$YICE_WORKSPACE/.scratch/youtube/dsh-inbox/`。Harness 循环运行 `kit/scripts/dsh-wait-next.sh <收件箱>`；中心往 `tasks/task-NNNN.md` 放任务，它做完写 `done/task-NNNN.md`。
- **任务怎么写**：用导演交代录屏师的口吻。写清这一镜给观众看什么、画面怎么走、时长、交到哪个文件夹、`progress.md` 写在哪。交回的内容包括：视频路径和时长、关键动作在第几秒、录了几次以及为什么选这一条、需要打码的地方。录糟了让它自己重录，最多 3 次。硬规矩只有三条：不在其他聊天窗口打字（任务明确指定的除外）、不改系统设置和账号、不删除或移动无关文件。
- **验收**：中心只读 done 文件，抽 3 帧核对。裁剪、打码、倍速放到 Codex 组装时做。
- **掉线**：同一个对话跑久了可能会停。任务放进去超过 10 分钟没人接，请用户在那个对话里说一句“继续”。
- **实测**：EP02 的 R1 访达镜头一次交付。真实点击，指针移动平滑；它自己检查了打码，30 张照片没有任何改动，录完把窗口恢复了原样。

## 备用：rec-demo 一条命令录完，Claude 不盯屏幕

每期准备一份私有参数 JSON：项目与窗口标识、按顺序发送的文字、每条的完成标志和超时，以及浏览器/访达的既有动作。先用 `bash kit/scripts/rec-demo.sh /absolute/params.json --dry-run` 审核镜头单；中心审核后把 `{"action":"rec-demo","params":"/absolute/params.json"}` 原子放入已授权终端中 rec-bridge 的队列。实际执行由本机确定性脚本完成，Claude 不轮询看屏幕，也不逐段指挥输入。格式和示例见 [rec-demo 文档](../kit/docs/rec-demo.md)。

执行器逐段重新标定窗口，确认开录后才输入；发送前逐字回读，已知卡片固定处理，未知状态停下留图。自动编号、停录、按事件裁首尾，并交付 take、events、index.md 与 failure.json。dry-run 不访问界面，不能代替中心后续实录验收。既有 bridge 需加载包含 rec-demo 的版本后再入队；改源文件不会自动升级已运行的进程。

下面保留 2026-11-14/15 的手动录制记录，供排查旧素材时参考；新一期使用上述标准入口。

## 历史手动方法

- 所有命令都通过 **Terminal 面板**执行（`mcp__terminal__run_in_terminal`）。Bash 工具没有录屏和辅助功能权限。
- 每一步写成一个脚本，用 `zsh <file>` 执行。用完关掉终端标签，一次最多开 6 个标签。
- 鼠标：用 `claude-code-video-toolkit/local/tools/rec/mouse` 控制（Swift CGEvent，移动带缓动）。点击会写进光标日志。
- 录制：`rec.sh <秒> <out.mov> x,y,w,h`，坐标用逻辑点，Retina 屏输出是 2 倍分辨率。
- 输入中文：每次 pbcopy 三个字再按 cmd+V，等 pbpaste 的内容对上了再粘下一段。
- Codex App：
  - 进程名是 `ChatGPT`，窗口可以设成 1440×805；
  - 录之前先收起侧栏，避免露出其他会话的标题。
- 浏览器画面：用干净的临时 Chrome profile，避免露出个人标签页。

## 每段交付

产出放在 `evidence/<ep>/rec-*/` 下。`index.md` 里每段一行，写这些：
- 文件、对应哪一幕、画面内容、像素、时长；
- 关键时间点：点击、输入开始和结束、发送、结果出现；
- 需要模糊的区域：用户名、路径、其他会话、项目名、邮箱；
- Codex 实际执行了哪些安装：装了什么、装在哪里（全局还是项目内），方便以后核对和清理。

## 边界（硬性）

- Finder 只执行参数文件中明确获准的演示动作；遇到系统授权框就停，由用户本人处理。
- 不点任何 macOS 权限弹窗。
- Codex 里的信任或权限确认由用户本人点，其他会话的转述不算批准。遇到这类确认就停下，报给中心，中心再问用户。
- 不改 Codex App 的设置，包括权限模式。
- 不录 Claude 的界面。
- 页面要求登录时，跳过那一段，回报中心。
- **防误发**（EP01 出过事故：脚本按固定坐标盲点输入框和发送键，前台窗口却已经切到别的线程，结果把一句话发进了定时任务里的日报线程）：
  1. 输入前先截图，或者读出窗口标题，确认前台是目标项目和对话，不对就中止；
  2. 点发送前再截一次图，确认输入框里是预期的文字，侧栏和标题里也没有别人的会话；
  3. 隔了会话、隔了天，都要重新核对，不能沿用上次摆好的窗口状态；
  4. 录制区域里出现侧栏，或者出现别的会话名，就不开录；
  5. 脚本里加一道守卫：标题对不上就直接退出。不准全程盲跑，到录完才截图。
- 录屏之前，请用户把与录制无关的 Codex 线程和定时任务界面关掉或收起；Stage Manager 会把窗口打乱，录制期间最好也关掉。
- 一旦误发：立即停手，删除这次录到的素材（里面带着别的会话内容），报告中心。由用户本人去那个线程查看，需要时撤回或忽略。录屏会话不再碰那个窗口。

## 和脚本对齐

- **权限模式**：Codex 处在“完全访问权限”时不会弹出安装确认。录之前先问用户这次用哪种模式，脚本和画面按实际情况写。EP01 用户选了保持完全访问，“点允许”那一幕就改成了“它在问你，点选项 1”。
- **长任务**：在参数文件中指定完成标志和超时，由 rec-demo 本地等待；超时自动停止并写失败报告。Claude 不再截屏轮询。
- **等待段**：录全，后期在画面里快进，并加倍速标记（×2 到 ×8）。
## 用 rec-shot 录

固定的 Codex App 操作可以写成镜头单，交给 `kit/scripts/rec-shot.sh` 执行；完整格式和 EP01 S4b-4“按旁白重新对齐”示例见 [rec-shot 文档](../kit/docs/rec-shot.md)。先运行 `--dry-run` 查看每步守卫条件，再由用户确认实际窗口、坐标与发送授权。

运行它的进程（Codex App）需要用户本人在 macOS 系统设置中，一次性授予“屏幕录制”和“辅助功能”权限。脚本不点击权限弹窗、不改 Codex 设置；Finder 仅执行已授权的参数步骤。权限未处理前只做 dry-run 和已有静态帧 OCR 测试。

每次粘贴和发送前，脚本强制核对目标标题与输入框 OCR 内容；匹配失败立即停止，截图留在私有目录。侧栏隐私规则写在私有镜头单里。每段产出事件日志和索引，时间基于录制启动时钟，首帧偏移未经校准。当前方案不需要模型逐步查看截图，但仍须遵守本文所有录制边界。
