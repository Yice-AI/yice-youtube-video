# 配音：写稿、生成、检测、修复

EP01 v6 的教训：ASR 核对全过、静音也压得很干净，用户一听仍有 6 处“卡”。原因不在剪辑：成片里的配音和处理后的配音逐个采样一致。问题出在**生成时字被拖长、句中降调**，以及**稿子写法**。只查“字对不对”和“静音多长”，看不出这类问题。v7 按本页做完以后，用户的听审结论是“顺了不少”。

## 1. 写稿：先写顺口，再生成

- **语序按口语：先说动作，再说耗时、结果。** 例如“生成二十秒的声音，大概要半分钟多”，不要写成“二十秒的声音大概要半分钟多生成”。
- **中英文之间不加空格**：“告诉Codex”“Codex应用”“M4芯片”“16G内存”。
- **不要机械地在每个 Codex 后面加逗号。** 这是早期为了压回音加的，结果把“Codex应用”读成了“Codex，应用”。
- **数字加单位要选好读的说法。** 比如“十一GB多一点”比“十一个多 G”顺。拿不准就让候选里几种写法各生成一条，听哪条顺。
- **容易听错的词换成不会听错的说法。** 比如“价签”会被听成“价钱”，改成“价格标签”。
- **转折、对比的句子要写出标点。** 比如“免费版没有，得用付费账号”，给模型一个停顿的位置。
- 朗读文本一改，SRT 同步改。实际送进 TTS 的文本要留底。

## 2. 生成后必跑两道检查

1. **内容**：ASR 核对漏字、多字、数字、专名。
   - 英文专名 ASR 常认不准（如 Qwen3-TTS）。整章匹配率 ≥ 0.97，且差异只落在专名或数字写法上，就算通过。
   - 同音别字要单独记下来，不能用模糊匹配放过去。
2. **韵律**：用卡顿检测器（`kit/scripts/voice-check.py`）扫全部章节。阈值已用用户标注的 6 处校准过（命中 6/6）：
   - **拖字**：句中一个字的时长 ≥ 本章中位数的 2.4 倍，且有效发声部分 ≥ 中位数的 2 倍。
   - **犹豫**：没有标点的地方出现 ≥ 60ms 的低能量间隔，且后一个字 ≥ 中位数的 1.7 倍；没有标点的间隔超过 150ms 也标出来。
   - **句中收尾**：音高下降 ≥ 4 个半音，同时前一个字 ≥ 1.7 倍、交界处低能量 ≥ 60ms。汉语本来就有降调，单看降调不能判错。
   - 每个间隔只算在一个字边界上，避免 Whisper 多字词造成重复告警。
   - 告警 0 条才能进组装。检测器不能代替听审，交付前仍要留试听切片。

## 3. 停顿按语义分档（按最终成片计时）

| 类型 | 区间 |
|---|---|
| 普通逗号 | 180–300ms |
| 转折、对比的逗号 | 300–450ms |
| 句末 | 300–450ms |

- 不再一刀切封顶。原本就落在区间内的停顿保留，不要压短。
- 1.08 倍提速和换幕多出的 200ms 都要先算进去，避免先压短、后叠加。
- 补停顿只能补在已核对过的词边界上，新增的静音两侧各做 10ms 淡化。不准剪词中有声音的部分。

## 4. 修复：整句替换

- 检测器标出来的句子，在句间自然的低能量处整句替换。不重做整章，也不在句中间拼接。
- 每句多个 seed 生成，用 ASR 加检测器一起挑。接缝做 10ms 交叉淡化。
- 核对替换前后音色连续（音色代理余弦 ≥ 0.94）、音高中位数偏差不超过约 3.5 个半音、响度一致。
- 替换后全部章节重扫，再按新的字时间重算换幕、录屏速度、字幕、音效和音乐。
- 每处修改前后各截 1–2 秒切片（clips/*-before.wav / *-after.wav），给中心和用户试听。

## 5. 后期参数（沿用 v3 方案）

- 呼吸声压低 12dB，超过 250ms 的截到 150ms。
- 交叉淡化 10ms，整体保音高提速 1.08 倍。
- 每章约 −16 LUFS；成片 −14 LUFS，真峰值 ≤ −1 dBTP。
