# 配音（v2）：Modal GPU 语义句组克隆、顺口写稿与五维卡顿门禁

## 为什么必须从本机 MLX 8bit 迁到云端 GPU 并重校准检测？

EP01 与 EP03 的连续实战暴露了旧配音链路的三个根因：
1. **本机 MLX 8bit 既抢占电脑内存（峰值 >11GB 导致卡顿），量化又损失了韵律自然度**，遇到专名、引号原话或数字时容易发紧、错读同音字（如“太素了→太树了”）。
2. **整章几十句拼成一条超长字符串（`max_tokens=4096`）单次自回归生成**，超过 25–30 秒后注意力漂移，出现句中突然发虚、吞音或微卡壳（如 EP03 第 4 句“答案是：两段都是”）。
3. **旧检测器漏检“相对能量塌陷（micro-dip）”**：旧静音扫描只卡 `−42 dBFS` 绝对静音，但真实听感里的“卡一下”往往是句中无标点处声门发紧、能量相对前后字骤降 `12–18 dB` 持续 `80–160ms`，绝对电平没跌破 `−42 dBFS` 就漏过去了，导致“指标全绿、一听还是卡”。

---

## 1. 写稿顺口规范（送入 TTS 前必查）

- **口语短句**：先说动作，再说结果或数字；单句控制在 6–20 字，超过 20 字拆成 `a/b` 子句。
- **中英文与数字零空格**：“AI剪的”“经理Claude”“百分之七十三”“一点五秒”。禁止在英文词后机械加逗号。
- **易混同音词主动换顺口词**：如“价签→价格标签”；多音字在发音词典显式映射，SRT 保留标准字面。
- **语义标点明确**：普通短停用逗号 `，`，转折/对比/揭晓前用冒号 `：` 或破折号/省略号，给模型明确的呼吸锚点。`〔核〕` 出处注记一律剥离不朗读。

## 2. 云端 GPU 合成架构（Modal 首选，Kaggle / 本机兜底）

### 2.1 后端优先级与隐私铁律
1. **首选：`--backend modal`**（调用已部署的 `MODAL_QWEN3_TTS_ENDPOINT_URL`，A10G GPU 运行 **bf16 全精度 `Qwen3-TTS-12Hz-1.7B-Base`**）：
   - **隐私红线**：读取本机私有 `brands/yice/voice.json` 参考音频，仅通过 HTTPS POST 请求体的 `ref_audio_base64` 内存直传给私有端点，返回 `audio_base64` 直接落本机磁盘；**严禁传 `r2` 参数，严禁把本人声音参考样本上传到任何对象存储桶或公开链接**。
   - **费用红线**：合成前核验 Modal `spend_limit_usd == 0`（只耗每月免费额度，8–10 分钟正片含多候选约 `$0.15–$0.35`）。
2. **备选 1：`--backend kaggle`**：当 Modal 免费额度耗尽或端点维护时，通过 Kaggle GPU 会话运行同一 `Qwen3-TTS-12Hz-1.7B-Base` bf16 批处理协议。
3. **备选 2：`--backend local`**：仅在完全离线调试单句时显式启用，正片生产不再默认跑本机 MLX。

### 2.2 语义句组（Semantic Chunking）共享 Prompt 批处理
- **禁止把 30–40 句整章拼成单条超长文本生成**，也禁止逐句孤立提取音色。
- 标准做法：每章按句号和语义自然切分为 **3–5 句一组（约 60–120 字，10–22 秒）** 的句组列表 `[chunk_1, chunk_2, ...]`，在**同一次 Modal 请求**中作为 batch 传入：
  - 服务端只提取 1 次 `voice_clone_prompt`，所有句组共享完全一致的音色锚点与热容器；
  - 每个句组生成 2–3 个采样候选（不同 seed / 微调采样），独立过 ASR 与五维韵律打分，自动挑出最顺畅的一条再按语义停顿档位（10ms 交叉淡化）拼回整章。

## 3. 重校准五维卡顿与韵律检测（`kit/scripts/voice-check.py`）

音频经过后期处理（呼吸声压低 12dB、>250ms 截到 150ms、保音高 1.08× 提速、章响度 −16 LUFS）后，必须逐句跑完以下 **5 道检查**，**0 告警**方可进入画面组装：

1. **ASR 严格内容与同音字核对**：
   - 使用离线 Whisper `large-v3-turbo`（仅传专名词表 `--asr-prompt`，严禁传原句台词作弊）。
   - 整章匹配率 `≥ 0.98`；除已登记专名拼写与数字等价写法外，**任何实词同音误读（如“太素→太树”“不猜→不拆”）一律标为 `homophone_suspect` 触发单句重生成**，不得用模糊匹配放行。
2. **句内相对能量塌陷（Micro-Dip / 声门卡壳检测 —— 针对 EP03“两段都是”校准）**：
   - 在句内**无标点连续词段**内，计算 10ms 帧能量相对前后相邻音节峰值的落差：若出现 **相对包络跌落 `≥ 12 dB` 且持续 `75–250ms`**（即使绝对电平高于 `−42 dBFS`），或包络出现双峰断续抖动，立即判定为 `intra_word_stutter`。
3. **无标点异常停顿与犹豫**：
   - 无标点字间低能量间隔 `≥ 90ms`，或 `≥ 55ms` 同时后一字时长 `≥ 本章中位数 × 1.65`，判定为 `unpunctuated_hesitation`。
4. **拖字与局部语速突变**：
   - 句中单字时长 `≥ 本章中位数 × 2.3` 且有效发声 `≥ 1.9` 倍；或相邻两句语速（字/秒）突变超过 `±38%`，判定为 `duration_or_rate_outlier`。
5. **句中塌调与句组接缝跳变**：
   - 非句末无标点处音高骤降 `≥ 4.0` 半音伴随低能量间隙（`mid_sentence_fall`）；
   - 语义句组拼接处前后音色余弦相似度 `< 0.94`、基频中位数跳变 `> 3.2` 半音或响度差 `> 1.8 dB`（`chunk_seam_jump`）。

## 4. 语义停顿分档与单句热修

| 边界类型 | 最终成片停顿区间（含 1.08× 后） |
|---|---|
| 普通逗号 `，` / 顿号 `、` | `180–280 ms` |
| 冒号 / 转折对比逗号 | `300–450 ms` |
| 句末 `。！？`（同幕内） | `300–450 ms` |
| 省略号悬念停顿（如 `我们……`） | `500–700 ms` |
| 换幕句间边界 | 下一句首字前预留 `200 ms` 视觉切点 |

- **不合格句自动整句/整组热修（`voice-repair.sh`）**：命中以上任一告警的句子，走 Modal GPU 多候选重生成该句（或所在 3 句微组），选出 ASR 1.0 且五维 0 告警的候选，在自然低能量句界做 10ms 交叉淡化替换，导出 `clips/*-before.wav` 与 `*-after.wav` 供抽查，并重算全片 `voice-timing.json` 与 `voice.srt`。

---

## 5. 标准命令

```bash
# Modal GPU 语义句组克隆配音 + 后期 + 五维卡顿检测 + 自动修复
bash kit/scripts/voice.sh episode/script.md \
  --output episode/voice \
  --backend modal \
  --candidates 3

# 单独对任意成片旁白轨做五维体检
python3 kit/scripts/voice-check.py \
  --audio episode/voice/chapter-00.wav \
  --alignment episode/voice/analysis/chapter-00-alignment.json \
  --text-file episode/voice/analysis/chapter-00-reading.txt \
  --report episode/voice/analysis/chapter-00-check.json
```
