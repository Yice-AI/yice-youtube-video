# 素材采集

先说明画面要证明什么，再找素材。需求单用 `kit/template/asset-needs.example.md` 讨论，用同目录 JSON 模板驱动批量网页采集。每项写：论点、素材类型、候选 URL、截取方式（静帧/滚动几秒/高亮哪句）、许可和镜头号；采集结果登记到每期 `asset-ledger.jsonl`。文件下载成功不等于该使用方式已获授权。

## 三路采集

| 路线 | 适用画面 | 执行与交付 |
|---|---|---|
| 资讯/网页实拍 | 官方发布页、产品界面、公开仓库、文档，用页面原文支撑具体论点 | `capture-web.mjs --needs`：1920×1080 静帧和 6–8 秒滚动。`news-card` 配来源名、采集日期、指定句高亮/划线与推近；采集日期不能冒充发布日期。 |
| 开放授权图像/视频 | 需要真实物体、场景或概念示例 | `open-media.mjs` 从 Commons/Openverse 按关键词检索，核对逐件许可与作者，再下载和登记署名。Openverse 索引还需核对原始来源页；当前入口为图像，Commons 可处理视频。 |
| 公开数据制图 | 对比、趋势、比例、过程关系 | 从原始数据来源记录数值、单位、时间范围和许可，用现有代码画面/图表组件重绘；保留数据来源，不直接搬用他人的成品图表。 |

录屏和 image2 仍是独立素材类型，在同一需求单中登记，由原有生产流程执行。批量网页脚本只读取 `news_capture`，不会拿任意 URL 当网页截图任务。命令、格式与输出见 [kit 素材入口](../kit/docs/assets.md)，资讯卡字段见 [配方文档](../kit/docs/recipes.md#news-card)。

## 许可账本与交付

每件素材至少保留 `id`、镜头、类型、原始来源 URL、采集日期、作者、许可名称/URL、署名文本、本地文件和 SHA-256。网页截图需记录引用来源；开放素材保留逐件许可证据，不能把“公开可见”写成“免费可商用”。品牌标志另按品牌使用规则核对。账本是随成片核查的依据，`.media/manifest.jsonl` 只负责复用文件。

## AI 实体素材

使用 [实体采集入口](../kit/docs/entities.md) 一次整理产品/公司/模型的官网首屏、关键段落、原生演示、官方 logo、明确允许媒体使用的 press kit 图片、GitHub README 演示及官方公告。素材按以下顺序选择：

1. 本人实测录屏。
2. 官网和官方发布页。
3. 官方 press kit / 媒体包。
4. GitHub / Hugging Face。
5. 论文和榜单。
6. 新闻或官方帖子。
7. 官方短视频片段：成片引用每段 ≤5 秒、静音、带来源，仅在评论语境中使用。
8. 图库实拍：只作为比喻空镜，不能冒充该产品的实测画面。
9. image2：补充无法取得的概念素材，保留生成记录。

在线 demo、试用框、匿名 Spaces 只登记入口并产出 Harness 录屏任务草稿，由中心审后派发。页面访问墙和拒绝自动访问的情况如实跳过，不绕过。

批量报告必须区分成功、跳过、失败。遇到一页打不开时继续其他项，保留原因；不要用错误页、登录页或挑战页冒充成功采集。媒体下载只选来源与署名完整的候选；选择 BY-SA 等素材时，署名和改编许可义务要随实际使用保留。来源规则见 [Commons](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia) 和 [Openverse](https://docs.openverse.org/terms_of_service.html)。

## 底线

- 只截取支撑论点所需的短片段，标来源及日期；具体引用用途仍按原内容权利核对。
- 第三方创作者画面只用于针对其内容或剪辑的评论拆解。截取支撑分析的短片段，全程静音，在 `reference_breakdown` 或对比卡上显式标注 `channel` 来源署名。禁止把未经评论的片段用作通用空镜，禁止保留原片声音。
- 不登录、不注册、不复制个人浏览器登录态；遇到登录墙、付费墙、访问挑战就跳过并记录。
- cookie 弹窗只选择拒绝非必要项；不遮盖或改写网页来伪造采集结果。
- 本轮只交原型和素材证据，不把新素材写入已完成的 EP01/EP02。
